DEV3 AI Translator & Cultural Localizer

AI translation with cultural adaptation, glossary, translation memory and delta sync for WPML, TranslatePress and Polylang. Version 1.0.1 · by DEV3 Technologies.

Overview

The plugin translates posts, pages, WooCommerce products and custom post types into the languages you configured in your multilingual plugin — and adapts them for each market instead of translating word for word: formal or informal address, metric or imperial units, currency, date and number formats, idioms and brand voice.

Source post→Segments (blocks, paragraphs, alt text, SEO…)→Translation memory→AI (only new / changed)→Glossary check→Translation saved through WPML / Polylang / TranslatePress
  • Block-aware: content is split into paragraphs, headings, list items, buttons, image alt texts and captions; markup, links, shortcodes and block settings are never shown to the AI and are rebuilt exactly.
  • Translation memory & delta sync: when you edit a source post, only the paragraphs you changed are sent to the AI. Everything else is reused — you see “X of Y segments reused” on every sync.
  • Glossary: brand names and product names stay untranslated; mandatory translations are enforced per language. Every answer is checked and corrected automatically.
  • Review: side-by-side editor for every segment. Human edits are protected from being overwritten by later syncs.
  • Bulk: translate whole post types into several languages in a background queue with progress, pause/resume/cancel, a cost estimate and a per-item log.

Requirements

  • WordPress 6.0+, PHP 7.4–8.3 with the OpenSSL extension, outbound HTTPS to generativelanguage.googleapis.com.
  • One multilingual plugin: Polylang (free or Pro), WPML (Multilingual CMS; String Translation for site strings), or TranslatePress (free or paid). Activate only one of them.
  • A Google Gemini API key (free tier available).
  • Optional: WooCommerce 7+ (products, attributes, variations), Yoast SEO or Rank Math (SEO fields).

Installation

  1. In your Envato download, find dev3-ai-translator-localizer.zip (the installable plugin — do not upload the whole bundle).
  2. WordPress admin → Plugins → Add New → Upload Plugin → choose the zip → Install Now → Activate.
  3. A new DEV3 AI Translator menu appears in the admin sidebar.

API key setup

  1. Open Google AI Studio → API keys and click Create API key.
  2. Go to DEV3 AI Translator → API Config, paste the key and click Validate & save. You should see “Connected — N models available”.
The key is encrypted in your database (AES-256-GCM) and never sent to the browser. You can also define it in wp-config.php:
define( 'DEV3TL_GEMINI_API_KEY', 'AIza...' );

For regular bulk work enable billing on the Google Cloud project behind the key; the free tier has low per-minute limits.

Quick start

  1. Make sure your multilingual plugin has at least two languages (e.g. English + German). The Dashboard shows the detected plugin and languages.
  2. Optional: add brand names to Glossary (e.g. “CloudDesk Pro”, Do not translate).
  3. Optional: check Locales — formality, units, currency and formats per language have sensible defaults.
  4. Open Bulk Translate, pick post types and languages, click Estimate cost, then Start translation.
  5. Open Review to read and polish the result. From now on, editing a source post syncs only what changed.

Polylang

Each translation is a separate post linked to the source through Polylang's translation group (pll_set_post_language, pll_save_post_translations). Categories, tags and product categories are translated and linked the same way (pll_save_term_translations); existing term translations are reused.

  • Enable the post types and taxonomies you want to translate in Languages → Settings → Custom post types and Taxonomies (e.g. Products, Product categories). Types that are not enabled appear greyed out in Bulk Translate.
  • WooCommerce with Polylang free: the plugin creates the translated product, copies prices and settings, translates local attributes and variation descriptions and creates matching variations. Stock is not shared between languages (that needs Polylang for WooCommerce).
  • “Translate site title & tagline” on the Dashboard writes Polylang string translations (Languages → Translations).

WPML

The adapter uses WPML's public hooks only: wpml_active_languages, wpml_default_language, wpml_post_language_details, wpml_object_id, wpml_element_trid and wpml_set_element_language_details. A translation is a normal post added to the source's translation group (trid); terms are linked by term_taxonomy_id. Site strings go through WPML String Translation (wpml_register_single_string, icl_add_string_translation) when that module is active.

WPML's own Translation Management can mark posts that were edited outside its editor as “needs update”. That is expected: our translations are written as regular posts. Use Review (not WPML's Advanced Translation Editor) to edit AI translations so your edits are protected from later syncs.

TranslatePress

TranslatePress does not create translation posts: it translates the page as it is rendered, using a dictionary of strings. The plugin therefore works in string mode:

  1. The post is rendered the way the front end shows it (title, content, excerpt).
  2. TranslatePress' own parser lists the strings exactly as it will look them up. Paragraphs that contain links or bold text are registered as TranslatePress translation blocks, so a sentence with a link is translated as one sentence.
  3. Translations are written into TranslatePress' dictionary with its own query class (status “machine translated”, or “human reviewed” for segments you edited in Review). Strings a translator reviewed in TranslatePress' visual editor are never overwritten.

Visit the page in the translated language (e.g. /de/about/) to see it. TranslatePress free supports one extra language; TranslatePress' own automatic translation does not need to be enabled.

Polylang and TranslatePress cannot be active at the same time (they both control language URLs). Activate one multilingual plugin. You can force a specific one under Settings → Multilingual plugin if several are installed.

Dashboard

Shows which multilingual plugin is in use, its languages with their cultural profile, translation-memory statistics (segments, human-reviewed, needing review, reuse rate, tokens), recently translated items and the queue.

Bulk translation & queue

  • Content — posts, pages, products and any custom post type your multilingual plugin translates. Counts show source-language items.
  • Only items without a translation — skip items that already have a translation in that language.
  • Re-translate AI segments — ignore AI entries in the memory (human-edited and approved segments are always kept).
  • Estimate cost — counts segments and characters, checks how many are already in the translation memory and estimates tokens and cost for the selected model (public list prices; your real bill is in Google AI Studio).
  • Jobs — progress bar, items done / failed / skipped, segments reused, tokens; Pause, Resume, Cancel, and a per-item log with links to Review.

Jobs run in the background with Action Scheduler (bundled with WooCommerce) or WP-Cron. While the Bulk screen is open it also processes the queue itself, so jobs complete even on hosts where background loopback requests are blocked.

Translation memory & delta sync

Every segment is stored in the table {prefix}dev3tl_tm keyed by the SHA-1 of its normalised source text plus the source and target locale. On each sync:

  1. The source is segmented again.
  2. Segments whose text is unchanged are taken from the memory (no AI call).
  3. Only new or edited segments are sent to the AI, in batches.
  4. The translation post is updated in place (same post, same URL).

With Auto-sync on update (Settings) saving a translated source post queues this delta sync automatically. The edit screen box and Review show “X of Y segments reused”. Identical sentences in different posts are translated once.

Manual edits: if someone edits a translation post directly, syncs skip it (option Protect manual edits) instead of overwriting their work. Use Review to make edits that survive syncs.

Review

Lists translated items with their languages. Open one to see the source and the translation side by side, segment by segment.

  • Edit any translation and click Save & update translation. The segment becomes Human-edited: future syncs (even “Re-translate”) never replace it, and the translation post is rebuilt from the memory immediately — no AI call.
  • Approve marks an AI segment as reviewed (also protected). Approve all shown approves the filtered list.
  • Markup placeholders like <1>…</1> stand for links or bold text and <2/> for a line break or shortcode. Keep them in your translation (you may move them); the editor warns you if one is missing.
  • Filter by Needs review to see segments that failed a glossary or markup check.
  • Sync now runs a delta sync for this item and language.

Glossary & brand terms

FieldMeaning
TermWord or phrase in the source language (matched as a whole word).
Do not translateKeep exactly as written: brand and product names, technical keywords.
Case-sensitiveOnly match (and require) this exact capitalisation.
Forced (locale)Mandatory translation for that language, e.g. checkout → Kasse.
NotesFor your team.

Relevant terms are added to the AI instructions; every answer is then checked. If a protected term was translated or a forced translation is missing, that segment is retried once with an explicit correction. If it still fails it is saved and flagged Needs review. Use Import CSV / Export CSV (columns term, dnt, case_sensitive, notes, de_DE, fr_FR…) to manage large glossaries.

Cultural adaptation (Locales)

OptionEffect
FormalityFormal or informal address with the right pronoun per language (Sie/du, vous/tu, usted/tú, Lei/tu, u/je…), or follow the source.
Measurement unitsMetric, imperial/US or keep. Measurements are detected (inches, feet, miles, pounds, ounces, gallons, °F, mph… and metric units) and the exact converted values are pre-calculated and given to the AI, which rounds them naturally. Optionally keep the original in parentheses.
Currency mentionsKeep as written, keep but localise the format (symbol position, spacing), or convert with a fixed rate you enter.
Date format, separatorsFull dates and numbers are rewritten in the locale's format (e.g. 14.03.2026, 1.234,56).
Adapt idiomsReplace idioms, puns and cultural references with natural local equivalents (“a piece of cake” → “kinderleicht”), or translate faithfully.
Brand voice / Custom instructionsFree text added to every request for this language.

Defaults are chosen from the locale (e.g. de_DE: formal, metric, EUR, DD.MM.YYYY; en_US: imperial).

What gets translated

  • Block editor: paragraphs, headings, list items, quotes, buttons, image alt text and captions, table cells, and text attributes of blocks (labels, placeholders, button text, captions…). Block settings, classes and IDs are preserved.
  • Classic editor and HTML: text split into paragraphs; inline formatting kept; alt, title, placeholder, aria-label and button values translated.
  • Never translated: URLs, shortcodes and their attributes, code (<code>, <pre>), scripts, styles, SVG, and anything inside an element with translate="no" or the class notranslate.
  • Title, excerpt and slug (the slug is generated from the translated title).
  • SEO: Yoast SEO and Rank Math titles, descriptions, focus keywords and social titles/descriptions (variables like %%title%% are kept).
  • WooCommerce: short description, custom attributes (names and values), variation descriptions; translated categories and tags.
  • Custom fields: list text meta keys under Settings → Custom fields to translate.
  • Taxonomy terms without a translation in the target language are translated and linked.

Translation engine

API Config → Translation engine: the model (default: the Pro model, gemini-2.5-pro, best for nuance; the Fast model is cheaper), thinking budget (1024), request timeout (150 s), segments per request (40) and characters per request (6000). Segments are sent as JSON with short stable ids and a response schema, so every answer maps back to its segment.

Updates

No licence key or activation is needed: every feature works as soon as the plugin is active. To update, download the latest version from your Envato Downloads page, then go to Plugins → Add New → Upload Plugin and upload the zip. WordPress offers to replace the installed version and keeps all your settings and data.

Troubleshooting

SymptomFix
“No supported multilingual plugin is active”Activate WPML, Polylang or TranslatePress and add a second language.
A post type is greyed out in BulkEnable it for translation in your multilingual plugin's settings.
Jobs stay “Queued”WP-Cron may be disabled. Keep the Bulk screen open (it processes the queue), or run a real cron (wp cron event run --due-now).
“Quota exhausted” / 429 errorsThe key hit its rate limit; enable billing or lower Segments per request. Failed items are listed in the job log; start a new job with “Only items without a translation”.
A translation was “skipped”Someone edited the translation post directly. Use Sync now in the edit-screen box to overwrite, or disable Protect manual edits.
Segments flagged “Needs review”A glossary term or markup placeholder was wrong even after the retry. Fix it in Review.
TranslatePress page still in EnglishClear page caches; make sure the language is published in TranslatePress settings and visit the language URL (e.g. /de/…).

REST API

Namespace dev3tl/v1, cookie authentication with a wp_rest nonce. Main routes: dashboard, estimate, jobs, jobs/create, jobs/{id}, jobs/{id}/pause|resume|cancel, glossary, locales, review/{post}/{lang}, translate. Review and translate require permission to edit that post.

Data

Tables: {prefix}dev3tl_tm (translation memory), {prefix}dev3tl_glossary, {prefix}dev3tl_jobs, {prefix}dev3tl_job_items, {prefix}dev3tl_usage. Post meta: _dev3tl_sync on sources (per-language stats), _dev3tl_source, _dev3tl_lang, _dev3tl_written on translations.

Privacy

The text of the content you translate (titles, content, excerpts, selected custom fields, SEO fields, term names) and your glossary/locale instructions are sent to Google's Gemini API using your API key, only when a translation runs (manually, in a bulk job, or by auto-sync after you save a translated post). Personal data in your content is sent too, so make sure your privacy policy covers AI processing by Google. No visitor data is sent. The API key is encrypted in your database and never sent to the browser. Usage logs (task, model, token counts) are stored locally and can be disabled.
